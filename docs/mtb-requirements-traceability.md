Status baseline: 31 August 2026, before implementation of the attached requirement set.  
Status values: **Implemented**, **Partially Implemented**, **Missing**, **Conflicting**, **Unsafe**.

The compact cells below intentionally keep this wide matrix readable. Paths are repository-relative.

the UCTSM domain/persistence now has explicit dependency mode, conditional action,
qualifier, activity-applicability, and confinement fields plus blocking validation;
and the shared schedule table now includes Applies To, Actual Date, and Status. See
`MTB_IMPLEMENTATION_HANDOFF.txt` for the exact completed boundary and remaining work.

## Principal contradictions and ambiguities

1. Repository documentation calls UCTSM authoritative, but the live product still uses MongoDB templates/instances and the UCTSM trial IDs are not linked to them. Implementation must resolve the linkage; merely rendering UCTSM screens would produce empty real-trial views.
2. The active extractor intentionally expands an open-ended repeat to 12 rows for compatibility. The finalized requirements explicitly prohibit presenting that technical preview cap as the schedule. The rule must remain stored and the preview must be labeled as such.
3. `_patient_visit_anchor()` currently falls back to the current time. The finalized anchor rule explicitly prohibits that behavior.
4. Active template edits can rematerialize future instances for already-enrolled patients. The finalized amendment rule says existing patients remain on their assigned version. Ordinary corrections inside an unapproved draft and new approved amendments therefore need separate commands and safeguards.
5. The document does not define automatic migration of existing patients; it explicitly excludes it in Phase 1. No migration workflow should be invented.
6. “Human confirmation where required” is clear for clinically significant schedule changes. Pure read-only previews, deterministic validation, and non-clinical display formatting do not require separate confirmation.
